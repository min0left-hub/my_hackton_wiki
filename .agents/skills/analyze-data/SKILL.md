# 데이터 분석과 시각화

## 시작과 범위
저장소의 AGENTS.md를 따른다. 참가자의 과제 해석 전에는 실행하지 않는다. 해석 후에도 분석·시각화 요청 또는 해당 작업을 포함하는 명확한 승인이 있어야 사용한다.
‘분석 방법만’ 요청에는 데이터 처리·파일 생성·웹서비스 구현을 시작하지 않는다. 분석 승인을 웹서비스 구현·도구 설치·외부 연결 승인으로 확대하지 않는다. 승인된 범위의 로컬 읽기·계산은 반복 승인 없이 진행한다.

## 분석 절차
1. **목적:** 누구의 어떤 판단을 돕는지, 필요한 결과가 수치·표·그래프·대시보드 중 무엇인지 실제 과제와 참가자 해석에서 확인한다. 이미 확정된 내용은 다시 묻지 않는다.
2. **데이터:** 제공 파일의 형식·행 수·열 의미·자료형·단위·날짜 범위를 확인한다. 한 행이 거래·상품·사람·이벤트 중 무엇인지와 식별 키를 파악한다. 관련된 빈값·중복·형 변환 실패·이상값·파일 간 연결을 확인한다. 중복처럼 보여도 서로 다른 거래일 수 있으므로 임의 삭제하지 않는다. 원본은 변경하지 않고 변환·제외 건수와 이유를 남긴다.
3. **집계 기준:** 필요한 지표마다 계산식·분모·집계 단위·포함/제외·기간 경계·정렬 기준을 해당되는 만큼 정한다. 원문·담당자 답·참가자 결정의 출처를 구분한다. 빈값과 0, 취소와 유효 건을 임의로 같게 취급하지 않는다. 결과를 바꾸는 미정 규칙은 담당자 질문으로 남기고, 담당자가 기준 없음을 확인하면 대안과 영향을 제시해 참가자 선택을 받는다. 미정 기준에 의존하는 확정 수치는 내지 않고 영향 없는 분석만 진행한다.
4. **계산:** 승인된 기준으로 필요한 분석만 수행한다. 합치기 전후 행 수와 중복 증가, 집계 전후 합계를 점검한다. 비율의 분모가 0인 경우·데이터 없음·누락을 구분한다. 추정·상관관계를 사실·원인으로 단정하지 않는다. 예상과 다른 값도 숨기거나 결과에 맞춰 원자료를 수정하지 않는다.
5. **시각화:** 변화는 선그래프, 범주 비교는 막대그래프처럼 목적에 맞는 단순한 표현을 고른다. 축·단위·기간·범례·필터·표본 수 등 해석에 필요한 정보를 표시하고 축 절단으로 차이를 과장하지 않는다. 대시보드는 카드·차트·표의 필터와 집계 범위를 일치시키고, 데이터 없음·오류·갱신 시각을 필요한 경우 표시한다. 실시간 연결 없이 실시간이라고 표현하지 않는다. 분석만 요청받았다면 화면 구현은 제안까지만 한다.

## 검증과 기록
- 원본의 작은 표본이나 별도 계산 경로로 합계·건수·비율을 검산한다. 같은 집계 함수를 다시 부른 것을 독립 검산이라고 하지 않는다.
- 전체 요구사항 검증과 결과 기록은 [verify-work](../verify-work/SKILL.md)를 따른다. 이 요청에 허용된 분석 결과 검증까지만 연결하며, 웹 화면 자동 조작은 하지 않는다. 사람이 확인할 경우 필터·입력·기대값을 안내한다.
- 요구사항·미정 기준·중요한 변경 정리는 필요한 경우 [requirements-planning](../requirements-planning/SKILL.md)의 방식으로 기존 문서를 갱신한다.
- 결과는 핵심 수치와 의미, 적용 기준과 출처, 품질 문제·제외 건수, 실제 검산 결과, 남은 한계를 짧게 남긴다. 실제 과제가 지정한 문서에 우선 기록하고 지정이 없으면 기존 요구사항·검증 문서를 활용한다. INDEX나 별도 분석 문서를 의무로 만들지 않는다.
- 제공 데이터만으로 해결 가능한 경우 추가 패키지·MCP·외부 서비스를 기본으로 요구하지 않는다. 외부 전송·공개·개인 API 키 사용은 하지 않는다.
