# my_hackton_wiki

AI와 과제를 진행할 때 참가자의 판단을 보존하고, 요구사항·결정·진행·검증을 파일로 이어가는 공개 준비 도구함입니다. 공식 시험 지침·정답·자동 기억 동기화 서비스가 아닙니다.

## 가장 먼저 읽을 파일
이 README를 읽은 코딩 에이전트는 다른 Skill·양식보다 아래 두 파일을 먼저 순서대로 읽고 적용합니다.
1. [AGENTS.md](AGENTS.md): 참가자 해석을 기다리는 조건, 승인 범위, 과도한 설계 금지, 시험 제한을 확인하기 위해 읽습니다.
2. [START_PROMPT.md](START_PROMPT.md): 새 과제 시작인지 이어받기인지 구분하고 지금 해야 할 일과 대기할 일을 확인하기 위해 읽습니다.

두 지침을 읽은 다음 실제 과제 README·제공 자료를 확인합니다. **이 저장소의 README는 도구함 사용법이며 실제 과제 요구사항이 아닙니다.** 실제 시험 규정과 과제 README는 참가자가 먼저 읽고 본인의 해석을 제시합니다. 에이전트는 그 해석 전에는 읽기 성공/실패만 알리고 기다립니다. 요약·기획·Skill 실행·구현·테스트·파일 생성은 시작하지 않습니다.

## 단계별 참조 규칙
아래는 한 번에 모두 읽거나 자동 실행하는 순서표가 아닙니다. 참가자의 현재 요청·승인 범위에 해당하는 파일만 필요한 부분을 읽습니다. 파일을 읽었다는 이유로 다음 작업까지 승인된 것으로 해석하지 않습니다.

| 언제 | 읽고 참조할 파일 | 참조 이유와 허용 범위 |
|---|---|---|
| 참가자가 과제를 해석한 뒤 검토·질문만 요청 | 실제 과제 README·관련 제공 자료·전달된 담당자 답 | 해석의 근거와 빠진 조건을 확인합니다. 요청한 검토·질문까지만 하며 기획 문서·코드·테스트는 만들지 않습니다. |
| 기획·요구사항 문서 정리를 요청 | [requirements-planning Skill](.agents/skills/requirements-planning/SKILL.md), 필요할 때 [요구사항 양식](templates/REQUIREMENTS.md) | 필수·우선·미확인·참가자 결정·AI 제안을 구분하고 동작 흐름과 진행 상태를 정리합니다. 기획 승인을 구현 승인으로 취급하지 않습니다. |
| 담당자 답·참가자 결정이 바뀌어 문서 반영을 요청 | requirements-planning Skill과 기존 요구사항·결정 문서 | 변경 출처, 기존 내용과의 차이, 구현·검증 영향을 반영합니다. 확정된 답을 다시 묻거나 코드까지 임의로 고치지 않습니다. |
| 구현을 명시적으로 지시 | 확정된 실제 요구사항·관련 결정·현재 코드·실행 방법 | 승인된 작은 기능을 구현하기 위해 읽습니다. 기획 Skill을 다시 돌리거나 새 기능·구조·도구를 임의로 추가하지 않습니다. 승인 범위에 필요한 통상 검증은 진행할 수 있습니다. |
| 데이터 분석·그래프·대시보드 작업을 요청 | [analyze-data Skill](.agents/skills/analyze-data/SKILL.md), 관련 원본·열 설명·확정 집계 기준 | 데이터 품질·단위·기간·분모·제외 기준을 확인하고 요청한 분석·시각화만 합니다. 분석 방법만 요청했다면 계산·화면 구현으로 넘어가지 않습니다. |
| 동작 검증·테스트 또는 테스트 시나리오 작성을 요청, 혹은 승인된 구현 범위의 필요한 검증 | [verify-work Skill](.agents/skills/verify-work/SKILL.md), 실제 요구사항·코드·기존 테스트, 필요할 때 [검증 결과 양식](templates/TEST_RESULTS.md) | 출처 있는 기대값과 실제 결과를 비교합니다. 시나리오 작성·탁상 시뮬레이션과 실제 실행을 구분합니다. 검증만 요청했다면 코드는 수정하지 않습니다. 사람이 확인할 화면 동작도 안내합니다. |
| 실행 오류·테스트 실패의 원인 확인 또는 수정을 요청 | [fix-errors Skill](.agents/skills/fix-errors/SKILL.md), 오류 원문·관련 코드·실패 조건 | 원인을 재현하고 좁히기 위해 읽습니다. 원인 확인만 요청했다면 수정하지 않고, 수정이 승인된 경우 최소 수정과 재검증을 합니다. |
| 중요한 선택·가정·변경 이유를 기록해야 함 | 기존 과제 지정 결정 문서, 필요할 때 [결정 양식](templates/DECISIONS.md) | 참가자 선택과 AI 제안, 근거와 한계를 구분합니다. 기존 제출 문서에 기록할 수 있으면 같은 내용을 별도 파일로 반복하지 않습니다. |
| 과제에서 협업 기록을 요구하거나 참가자가 기록을 요청 | 기존 지정 문서, 필요할 때 [협업 기록 양식](templates/COLLABORATION.md) | 실제 위임·선택·수정·확인만 요약합니다. 대화를 전부 복사하거나 하지 않은 확인을 만들지 않습니다. |
| 새 대화·세션으로 이어받음 | AGENTS.md → START_PROMPT.md → 짧은 인계와 필요한 기존 문서·현재 파일, 필요할 때 [진행 양식](templates/PROGRESS.md) | 완료·진행 중·다음 작업·미검증·실행 방법·승인 범위를 실제 파일과 대조합니다. 이전 대화가 자동 공유된다고 가정하지 않습니다. |
| 도구함의 출처·설치본 여부를 확인 | [SOURCES.md](SOURCES.md) | 자체 작성 Skill과 참고 원본을 구분하기 위해 읽습니다. 참고 링크가 있다는 이유로 원본 저장소를 자동 다운로드하지 않습니다. |
| 이 도구함에서 실제 확인된 범위가 궁금함 | [VALIDATION.md](VALIDATION.md) | 형식 점검·모의 검토·실제 시험 환경 검증을 구분합니다. 과거 검사 기록을 현재 과제의 통과 근거로 사용하지 않습니다. |

## 문서와 실행의 공통 원칙
- 현재 요청을 만족하는 최소한의 파일·기능·검사만 다룹니다. 다음 단계, 무관한 테스트, 패키지 설치, MCP 연결, 새 문서 생성은 자동으로 하지 않습니다.
- 실제 과제가 지정한 제출 파일명·경로와 기존 문서를 우선합니다. templates는 빈 참고 양식이며 전부 복사하거나 작성할 의무가 없습니다. 지정이 없을 때만 실제 프로젝트의 wiki/REQUIREMENTS.md·wiki/TEST_RESULTS.md 등을 필요한 만큼 사용합니다.
- 도구함 원본의 templates나 Skill에 실제 담당자 답·시험 데이터·결과를 넣지 않습니다. Skill은 작업 방법이며 실제 과제 사실은 과제 문서에 기록합니다.
- 요구사항 문서 상단의 동작 흐름은 구현 상태와 검증 상태를 분리합니다. 기획 시에는 미착수·미실행으로 두고 실제 근거가 있을 때만 갱신합니다. INDEX는 사용하지 않습니다.
- Skill 간 연결은 참고 경로입니다. 다른 Skill을 참조하라는 문구가 있어도 현재 승인 범위를 넓히지 않습니다.

이후에는 내가 요청한 단계에 필요한 Skill과 문서만 참조해.

## 기억과 공유
새 세션이 문서를 자동으로 전부 읽거나 다른 세션 대화를 자동 공유하는 것은 아닙니다. INDEX는 사용하지 않습니다. 새 세션으로 넘어갈 때만 완료·진행 중·다음 작업·미검증·실행 방법·승인 범위를 짧게 정리하고, 필요한 기존 문서를 읽도록 요청하세요. 실제 파일을 확인한 내용과 문서 주장도 대조합니다. 같은 파일을 여러 세션이 동시에 수정하지 않게 작업 범위를 지정합니다.

## 시험 중 사용
공개 저장소에는 범용 지침과 빈 양식만 유지합니다. 실제 과제 문제·개인 응시 링크·첨부자료·대화·코드·로그·완성된 위키는 시험 작업 공간에만 두고 이 저장소로 업로드하거나 Git Push하지 않습니다. 공개 자료의 허용 범위와 공개 유지 기간은 최신 운영 안내를 따르세요. 이 저장소를 읽었다고 Skill이 설치·인식됐다고 주장하지 않습니다. 지원되지 않으면 필요한 SKILL.md를 직접 읽혀 사용합니다. 실제 제출 문서와 파일명은 과제 안내가 우선입니다.

## 데이터 분석이 필요한 경우
참가자가 먼저 과제를 해석한 뒤 필요한 범위만 요청합니다. 예: `analyze-data Skill을 읽고 제공 데이터의 품질과 집계 기준을 확인해줘. 아직 웹서비스는 구현하지 마.`
계산·그래프 작성까지 원하면 그 범위를 함께 지시합니다. Skill 파일을 받았다고 자동 발견·설치가 보장되지는 않으며, 인식되지 않으면 해당 SKILL.md를 직접 읽도록 요청합니다.
